# Runtime Codemap: Flow, Run, Economy, Facilities & Meta

Last Updated: 2026-11-14 01:07:46 (KST)

> Purpose: Class map for game flow, run state, economy, facilities, rewards, meta progression, and flow UI. | Parent: [codemap/README](README.md) | Related: [CombatAndSquads](CombatAndSquads.md), [design/PrepEconomyMeta](../design/PrepEconomyMeta.md)

Base path: `Assets/_Project/Scripts/Runtime/`. Assembly: `ProjectNeo.Runtime`. Namespace: `ProjectNeo.<Folder>`.

| Folder | Key Classes | Role |
|---|---|---|
| Economy | `Cost`, `Wallet`, `MaterialDefinition` | Costs and wallet storage for gold and various monster material types. |
| Economy | `ItemDefinition`, `Inventory`, `EconomyConfig`, `ItemShop` | Equipment/consumable definitions, inventory containers, sale ratios, shop roll and trade logic. |
| Economy | `CraftingRecipe` | D-6 fixed blacksmith recipe (item + `Cost` gold/materials), listed per level in `FacilityLevel.recipes` (Q-35). |
| Facilities | `FacilityDefinition`, `FacilityState`, `SoldierTraining` | Per-facility level progression, inventory pools, upgrade costs, and stat modifiers. D-4: `SoldierTraining` (pure C#) swaps the current Training Ground level `soldierModifiers` onto a grunt `StatSheet` under one source, so re-applying never stacks. |
| Flow | `GamePhase`, `BattleOutcome`, `GameFlow`, `RunProgress` | Pure C# flow state machine: Title → Prep → Battle → Reward (if victory) → Next Stage Prep, or Run Results (if defeat) → Title. Illegal transitions return false without state mutation. `RunProgress` maintains current run stage, discarded upon return to Title. |
| Flow | `GameSession`, `SceneCatalog`, `SceneSwitcher`, `GameDirector` | `GameSession.Flow` persists across scene loads, instantiated per session. Scene names defined in `SceneCatalog.asset`. Scene transitions routed via `SceneSwitcher`. `GameDirector` starts a new run when Game scene is loaded directly and navigates to Title on exit via `GameSession.Flow.PhaseChanged`. |
| Flow | `GamePhaseView` | Coordinates cameras, input, and UI per phase in Game scene. Prep defaults to 1st-person; toggles to build camera/placement/HUD at construction station; Battle enables 1st-person/commands and locks cursor; Reward/Results disable both and unlock cursor. NavMesh rebuilt before unit activation. |
| Flow | `PreparationInteractionSettings`, `PreparationInteraction`, `ConstructionStation` | F interaction to open construction station and Esc to exit (`Data/GameFlow/Interaction.asset`). View/input toggled by `GamePhaseView`; prompts/reticle rendered by `GameFlowHud`. |
| Flow | `GameBattleSettings`, `GameBattleController`, `PreparationStation`, `BattleStartStation` | Connects enemy spawning, siege combat, win/loss, and retreat logic to GameFlow Battle phase (`Data/GameFlow/Battle.asset`, `Siege.asset`). FLOW-01: triggered by holding B for 1 second in prep exploration via PreparationInteraction (explicit battle reference wired in Game.unity and GameBattleSetup). Interaction.asset stores binding/duration; HUD shows progress, release/modal/focus loss cancels, held keys cannot restart after modal/phase transitions. Legacy banner F is disabled. Tallies termination cause, kill counts and Q-30 retreat counts per enemy prefab, passing results (with `GameSquadMorale.HasFled`) to `GameRunLink.TryFinish`. B-8.2: `Awake` adds `GameSquadMorale` when `GameBattleSettings.Morale` (`Data/GameFlow/Morale.asset`) is set; exited routed allies are inactive so `AlliesAlive` excludes them. |
| Flow | `GameRunLink` | Links Game scene to run data (C-1~2). Constructs `RunState` during initial prep via `GameFlow.AttachRunState`; captures castle into `BattleInput`; applies `BattleResult` once; heals survivors via `Health.RestoreFull`. `TryRecruit` (D-0b/D-4) adds recruited grunts to `RunState` and `SquadCommandCenter` via `RunUnitBinding.BindNew`; `ApplyTraining` applies barracks bonuses. D-3: `TryHire` adds a hired hero to run and scene with a shared `Character` and sets the scene leader; reserve heroes are deactivated at battle start and reactivated in prep (Q-48). C-3: next prep start runs `CleanUpSquadsAfterBattle` (scene `RemoveFallen`, then run `RemoveEmptySquads` mirrored by scene `RemoveSquad`). |
| Flow | `GameUnitSpawner` | D-0b/D-4 scene spawning on `GameBattleController`. `Recruit(definition, facility, preferredSquad)` instantiates `SoldierDefinition.UnitPrefab` inactive, configures AI/fall settings, places in front of `FacilityStation`, walks to squad gather point. `RecruitAtBarracks` pays cost and calls `ApplyTraining`. Wired by `GameUnitSpawnSetup`. D-3: `HireAtTavern(hero, captainOf)` builds the hero body from `HeroDefinition.UnitPrefab` (grunt prefab reconfigured with the hero), activates it in front of the tavern so its `Character` exists, then walks captains to their squad. |
| Flow | `GameRewardController` | C-4 Victory rewards. On Reward phase, evaluates `StageReward` from last victory result and run seed; deposits once into run wallet/inventory and adds Commander EXP + Unlock Points to `GameSession.Meta` (`Data/GameFlow/Rewards/StageRewards.asset`, `Meta.asset`). |
| Flow | `GameBuildEconomy` | D-2 Construction/repair economy. Grants starting gold from `RunStart.asset`; gates placements via `PlacementController.ConfirmGate`; powers `Dismantle`, `Repair All`, and `EconomyStatus` UI during prep only. |
| Flow | `GameFacilities`, `FacilityStation` | D-0/D-1/D-5/D-4 facility pop-ups (`FacilityPanel`). Freezes movement/look via `GamePhaseView.EnterPanel`; Esc exits. Supports upgrades (`TryUpgradeFacility`), Shop buy/sell rows (`RowTemplate`, restocks once per prep) and gold re-roll (PREP-02: `TryReroll`, `Button_Reroll` shown only for the Shop; added via `GameFacilitySetup.ApplyRerollButton`), and Barracks (`TrainingGround`) recruit/squad columns + training bonus display (`BarracksSetup`), and Smithy (D-6) recipe craft rows + equipment-only sell rows (`TryCraft`, `TrySellEquipment`; recipe data via `GameFacilitySetup.CreateSmithyData`). D-3: Tavern hire rows (`TryHire`) and captain-squad / reserve choice (`ChooseCaptainSquad`); restocks once per prep. |
| Flow | `GameEquipment` | D-7 Player equipment UI (`I` during prep opens `EquipmentPanel`). Equips/unequips between stash and player `Character` (`RunState.TryEquip`/`TryUnequip`). D-3: top row cycles the target hero (player + hired heroes, `SelectedHero`/`NextHero`). |
| Flow | `GameSquadOrganization` | D-8 squad organization UI (`O` during prep via `PreparationInteraction.OrganizationRequested`, `OrganizationPanel` from `SquadOrganizationSetup`). UI-01 card layout (Q-49): one card per squad (captain row + grunts) in a horizontal scroll, plus new-squad and reserve-hero cards; `Select(unit)` then `DropOnSquad(index/-1)` or `DropOnReserve()` (moving a captain to another squad clears the old one first). Uses `GameRunLink.TryMoveSoldier`/`TrySetCaptain`, which change run and scene squads together and remove emptied squads from both. |
| Run | `RunState`, `RunUnit`, `RunHero`, `RunSoldier`, `RunConfig`, `RunSquadSetup` | Pure C# run container (C-1a): wallet, inventory, heroes, grunts, squads (`Army<RunUnit>`), castle records. Distinguishes runtime `Id` from definition asset. Starting config in `Data/GameFlow/Build/RunStart.asset`; Game scene builds player/squads from scene layout. Discarded on return to Title. D-8: `CheckMoveSoldier`/`TryMoveSoldier` (one grunt, null target = new squad, emptied source removed with captain to reserve, receiving morale kept), `ReserveHeroes`, `LeadingSquadOf`, `CheckSetCaptain`/`TrySetCaptain` (reserve heroes only; `AllowPlayerCaptain` off per Q-32 interim), enum `OrganizeCheck`. C-3: `RemoveEmptySquads` (Q-50: removes squads with no grunts and no captain, returns indices high to low; no-op while a battle is pending). D-3: `TavernOffers`, `RestockTavernIfNeeded` (seeded per prep, excludes heroes in run or fallen), `CheckHire`/`TryHire` (BattlePending → NotOffered → NoSquad → NotEnoughFunds, enum `HireCheck`; captain swap sends old captain to reserve). `HeroDefinition` gains `Tier` and `UnitPrefab`. |
| Run | `RunUnitBinding<T>` | Pairs scene GameObject units with run unit IDs. Builds `RunState` from scene setup and `BattleResult` from combat survival (B-8.2: optional `isFled` → `UnitFate.Fled`, death first; optional per-type `retreats`). Run player shares `Character` with scene player. |
| Run | `CastleState`, `BattleInput`, `BattleResult` | Records castle placement, layers, rotations, HP, mounted weapons (`Capture`/`TryRestore`, bottom-up). `RunState.Apply` checks battle index for single application; dead grunts removed, dead heroes moved to `FallenHeroes` with gear; `Fled` units stay in their squad. `BattleResult.EnemiesRetreated` (B-8.2/Q-44) counts Q-30 retreats per enemy type separately from `EnemiesKilled`. Format reviewed in C-1a-confirm; B-8.2 owns the final rout/exit format (Q-44 removed enemy morale, so no enemy rout reason). |
| Run / Facilities | `RunState.Facilities`, `FacilityDefinition.DisplayName` | `FacilityState` per type (initial level 0); assets in `Data/GameFlow/Facilities/Facility_*.asset`. `Shop`, `RestockShopIfNeeded`, `TryBuy`, `TrySell`, `TryUpgradeFacility` (`Data/GameFlow/Economy.asset`). PREP-02 re-roll: `ShopRerolls`, `ShopRerollCost`, `ShopStockedLevel`, `ShopRerollSeedFor`, `CheckShopReroll` (BattlePending → NotStocked → NotEnoughFunds, enum `ShopRerollCheck`), `TryRerollShop(isAvailable)`; cost data `EconomyConfig.GetRerollCost` (base + step × re-rolls this prep). D-6: `Smithy`, `CraftableRecipes(isAvailable)`, `CheckCraft` (BattlePending → NotCraftable → NotEnoughFunds, enum `CraftCheck`), `TryCraft`, `TrySellAtSmithy` (equipment only, Shop sell ratio). |
| Run | `BuildCostTable`, `PieceGoldCost`, `WeaponGoldCost`, `BuildEconomy` | Build cost table asset (piece/weapon gold, past refund ratio, repair gold per HP) and pure C# refund/repair logic (heaviest damaged first). |
| Run | `StageRewardTable`, `KillReward`, `StageReward` | Reward table asset and deterministic `StageReward.Roll` via `IRandomSource`. `RunState.ApplyReward` enforces single payout per battle via `SeedFor`. |
| UI | `TitleScreen`, `GameFlowHud`, `RuntimeSystemFont` | Title callbacks, phase display, prompts, troop counters, reward breakdown, prep gold balance, runtime Malgun Gothic applicator. Not final UI. |
| Meta | `PerkDefinition`, `PerkLoadout`, `PerkSpecialEffect`, `MoraleBoostPerkEffect` | Perk definitions, point allocation/resets, event-driven perk hooks. Runtime combat wiring deferred. |
| Meta | `MetaProgress`, `MetaConfig`, `CommanderProgression`, `UnlockGacha` | Persistent meta state, Commander EXP, perk points, reincarnation conversion, duplicate-protected gacha unlock pool. Disk persistence pending. |
