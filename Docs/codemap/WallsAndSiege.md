Valley rule (`SIEGE-14` spike, off unless `BuildGridDefinition.forbidValleys`): `BuildLayout.Check` returns `PlacementIssue.Valley` (=12) when a wall-like placement would leave a neighbour's top lower than both cells on one axis; `BuildLayout.ValleyFill` gives how many 1x1 wall/bastion pieces a gap needs (0 = forbidden) and `ConstructionWorld.TryPlace` stacks that many; `BuildLayout.RemovalMakesValley` guards `TryDismantle`; `ConstructionWorld.Collapse` destroys all storeys above the collapsed piece (`CollapseAbove`) instead of settling them down. `ConstructionWorld.GeometryRoot` exposes the NavMesh collection root. Tests: EditMode `ValleyRuleTests`.

Castle kit dressing (`SIEGE-14` spike, `feature/siege-14`, used only by `SyntyGridSpike.unity`): pure `Walls/CastleKitRules.Collect` turns the layout into `CastleKitPlacement`s (`CastleKitPiece` Panel=0, PanelAccent=1, Pillar=2, Floor=3, Battlement=4, BattlementCap=5, GateOuter=6, GateInner=7, WallStairs=8, InnerRelief=9, RubbleTop=10, RubbleMiddle=11, RubbleBottom=12, RubblePile=13, PanelHalf=14, BrokenTop=15, BrokenMiddle=16, BrokenBottom=17, BattlementHalf=18, CornerStairs=19, FloorHalf=20, TowerPanel=21, TowerArrowslit=22, TowerDoor=23, TowerCorbel=24, TowerCorbelCorner=25, TowerCap=26, RoomStairs=27, RoomCollider=28, RoomLink=29, RoomPost=30, CornerStairsOpen=31; prefab pivot in castle-local metres + yaw (+ optional mirror and vertical scale); a breach cell gets a V ruin of broken fragments and rubble caps descending from each intact neighbour, plus a low pile, and stairs landing on the breach cell keep standing with a rubble cap on their end; a collapsed bastion cell (`rubble`) gets only a pile; neighbours stay intact): panels on each wall/bastion storey face not covered by a same-level piece or a remembered breach (outward faces use the `Wall_04` accent at grid intervals, courtyard faces get a `Wall_Panel_Stone_02` relief on the top storey), shared joint pillars, a floor and battlement faces (`BattlementRules.Faces`) on tops, outer/inner frames plus passage side panels on gate cells (outer = rotation side), and a walkway-centred wall stair on a lower walkway next to a column one storey higher. Outside uses the default-castle enclosed rule. `Walls/CastleKitDresser` (on `ConstructionWorld`; the Game uses it since `SIEGE-19`) rebuilds only changed cells on `Changed`, hides the placeholder `Visual` of dressed pieces, animates the gate (`PortcullisRaised` folds the portcullis into the arch top, doors swing inward while `IsHeldOpen`, both hidden when breached), records collapse breaches from `PieceCollapsing` (bastions as rubble-only cells; seeded bastions are left out of the always-inside set), parents its container under `ConstructionWorld.GeometryRoot` so kit colliders (pillars, `Wall_04`, stairs) enter the NavMesh, and requests a NavMesh rebuild when those change. Prefabs: `Walls/CastleKitSettings` (`Data/SyntyGridSpike/CastleKit.asset`, module 5m, accent spacing, stair width). Spike-only `Walls/CastleKitTestKeys`: `P` portcullis, `O` hold gate open, `B` breach/repair gate, `K` collapse the aimed wall, bastion or stairs, `L` toggle `CastleKitDresser.Look`. Tests: EditMode `CastleKitRulesTests`.

Game castle kit (`SIEGE-19`, `feature/siege-19`): `Data/GameFlow/Build/CastleKit.asset` (shared prefabs in `Prefabs/CastleKit`) is applied to `Game.unity` by `Editor/GameCastleKitSetup` (menu `ProjectNeo/Setup/Apply Castle Kit To Game Scene (SIEGE-19)`; it updates the asset in place and adds `CastleKitDresser` with `battlementColliders` off, and sets `CastleBattlements.showVisuals` off, so the Game kit battlements are visual only and `CastleBattlements` keeps collision, allied `ShotCover`, ladder sill and crenel stand points; known mismatch with the rule sizes until `SIEGE-20`). `CastleKitDresser.staticBatching` (default on, Play Mode only) combines each dressed cell root with `StaticBatchingUtility.Combine`, except the gate cell; 391 of 419 kit renderers are batched. `ConstructionWorld.Awake` calls `CastleKitDresser.BuildBeforeNavigation` (after `CastleBattlements`) so the kit colliders go into the first NavMesh bake instead of queuing a second one. `CastleKitRules` adds convex-corner turrets: `CastleKitPiece.CornerTurret = 33` (`Prefabs/CastleKit/CornerTurret.prefab`, `SM_Bld_Castle_Wall_Tower_M_01`, visual only, `CastleKitRules.CornerTurretDrop` 2.5m below the top): one per pair of adjacent outside, empty faces of the top Wall placement of a cell; a collapsed corner drops its turret with the cell. `StairRoomRules`: a gate column (level 0 `Gate`, all levels above `Wall`, 3+ storeys) is a room column like a wall column (private `IsRoomColumn`); the raised portcullis hides inside the outer wall panel of the storey above the gate. Tests: EditMode `StairRoomRulesTests`, `CastleKitRulesTests` (`RingCorners_GetOneTurretEach_AtTheTopOfTheCorner`). Dev keys: `Flow/GameDevKeys` ([FlowRunEconomy](FlowRunEconomy.md)).

Wide cells (`SIEGE-35`, spike only, `SyntyGrid75Spike.unity`): kit pieces are no longer scaled by cell size ÷ module on every axis; they keep the module size (height, thickness, stairs, module-metre settings) and the rules put the horizontal fit into `CastleKitPlacement.StretchX/StretchZ`. `Walls/CastleKitLook` (`Stretch = 0`, `Compose = 1`, passed to `CastleKitRules.Collect(..., kitLook)` from `CastleKitDresser.Look`): `FacePieces` covers a face with one module stretched to the cell (`Stretch`) or a module plus a half (`PanelHalf`, `BattlementHalf`, new collider half `CastleKitPiece.RoomPanelHalf = 32` for stair rooms and tower rooms; same piece squashed for corbels; `Compose`), with joint pillars/caps at the 5m joint (joint keys on a 0.25m lattice); `keepModule` keeps gate frames unstretched and centred with 1.25m fillers in both looks. `FloorCell` stretches one floor or composes one full plus three `FloorHalf`. Outside stairs keep the module run; `CornerStair` pivots one module back from the higher cell's edge. Breach halves and the cross-section stretch to the cell; `AddBreachWedge` adds a tilted `RoomCollider` under each V half (ground gap stays open). Tests: EditMode `CastleKitWideCellTests`.

Towers (`SIEGE-14` spike, `feature/siege-14`): `Walls/BuildPieceKind.Tower=4` and `PlacementIssue.TowerNeedsWall=13` / `TowerStack=14`. Pure `Walls/TowerRules`: `Check` (outside cells against a same-level wall like `BastionRules`, nothing but tower tiers on a tower, tower tiers only on towers), `Tiers` (how many tiers `ConstructionWorld.TryPlace` stacks: one above the tallest touching wall or gate column, capped by `MaxLevels`), `RoomOf` (top-storey room: walkway-level inner face, door cell, stair cell, rise face) and `StandingOn` (feet on the roof of a piece with occupant modifiers). `ConstructionWorld.CheckPlacement` runs it after `BastionRules`. `BuildPieceDefinition.OccupantModifiers` (`SetOccupantModifiers`) holds stat modifiers for allied ranged attackers on that piece's roof; `Walls/TowerOccupantBuff` (on `ConstructionWorld`, spike only for now) applies them every 0.25s with the definition as the modifier source and removes them when the unit leaves, is no longer eligible, or the component is disabled. `CastleKitRules.AddTower` dresses towers (corner-only pillars, `TowerArrowslit` / `TowerDoor` / `TowerPanel` top storey, interior `WallStairs`, `FloorHalf` over it, `TowerCorbel` / `TowerCorbelCorner` / outward `Battlement` / 1.2× `TowerCap` on the roof); walkway stairs are never generated toward a tower. `CastleKitDresser.UpdateTowerRoom` disables the top tier's box collider when it has a room and adds a `HollowTop` child with roof slab boxes around the stair opening; a collapsed tower is a rubble-only cell like a bastion. `ConstructionHud.SelectTower` and the tower placement issue texts are used only by the spike scene.

Interior stair rooms (`SIEGE-27`, spike only): pure `Walls/StairRoomRules` (`MinStoreys = 3`): `Collect` / `TryGet` find stair-room cells: in each group of joined 3+ storey finished `Wall` columns, the cells touching a 1- or 2-storey walkway (wall, bastion or gate top; towers excluded) at a row end (at most one group neighbour), else the first touching cell; other cells stay solid. Fallen neighbours count through `fallenTops` (cell → pre-collapse top height). The result `Walls/StairRoom` (readonly struct) has `BaseLevel` (lowest touching walkway floor), `TopLevel`, `FootFace`, `FirstFlightFace`, and per-storey walkway door bits `Doors(level)` / `HasDoor`. Stair cells pick foot and first-flight faces that keep the most walkway doors; the foot and far faces are reachable on every storey (middle corridor), the second-flight side only on the base storey, the first-flight side never. `IsTallWall` suppresses outside `WallStairs` toward any 3+ storey wall column; outside stairs stay only for 1↔2. Pure `Walls/StairWell` (reusable for towers, `SIEGE-29`): one-cell switchback per storey (two 45° half-storey flights hugging the side walls, `flightWidth`, with a floored middle corridor from the foot strip to under the landing), with `Landing`, `Hole` (ceiling opening over the second flight plus `holeOverhang`), `CeilingAreas`, and link points `LandingFirst`, `LandingSecond`, `FootFirst`, `FootSecond`. `CastleKitRules.Collect` gained optional `fallenTops` and `rooms` parameters; `AddRoom` dresses each room storey with `RoomStairs` visuals, `RoomCollider` ramps, landing and ceiling slabs, scaled `Floor` areas (the roof walkway of a room cell gets an opening instead of a full floor), and `RoomLink` NavMesh links across each landing and each upper foot strip (NavMesh erosion with agent radius 0.5 would otherwise cut those turns). Room storeys use collider panels (`TowerPanel`, `TowerDoor` = `Wall_Door_01` for doors, `PanelAccent`) and line faces shared with same-level neighbours (one lining between two stair rooms); `AddPost` puts a `RoomPost` (`SM_Bld_House_WoodBeam_01`) under each upper-flight post down to the floor. New `CastleKitPiece` values: `RoomStairs=27` (`Stairs_Wood_Straight_01`, no collider), `RoomCollider=28` (no prefab, box collider), `RoomLink=29` (no prefab, `Unity.AI.Navigation.NavMeshLink`), `RoomPost=30`, `CornerStairsOpen=31` (corner stair model without collider). `CastleKitRules.AddSideEntryCornerStair`: a 1-storey corner whose only way in is a stair-room door on its side gets the quarter-turn stair boarded from the side (`CornerStairsOpen` + `RoomCollider` ramps and landing, upper ramp reaching the higher top at the cell edge, `RoomLink` from the door floor onto the lower flight). `CastleKitPlacement` gained `StretchX`, `StretchZ`, `Tilt`. `CastleKitSettings` gained `RoomWallInset` 0.31, `RoomLandingDepth` 1, `RoomSlabThickness` 0.2, `RoomRampThickness` 0.15, `RoomHoleOverhang` 0.6, `RoomFlightWidth` 1.46, `StairPostNear` / `StairPostFar`, `RoomPostHeight` 2.5, `RoomPostThickness` 0.95 (module metres). `Walls/CastleKitDresser` remembers `fallenTops` from `PieceCollapsing` and exposes `Rooms`; `UpdateStairRoom` disables the wall piece box collider on room storeys and adds a `HollowTop` roof slab under the top room storey so build mode can still pick it. Placement: `PlacementIssue.StairsGroundOnly = 15` and `BuildGridDefinition.GroundStairsOnly` (`Create(..., groundStairsOnly)`), checked in `BuildLayout.Check`; text in `ConstructionHud` only (Game `SiegeHud` waits for `SIEGE-18`). Tests: EditMode `StairRoomRulesTests`.

Gate machicolations (`SIEGE-12`, `feature/siege-12`): pure `Walls/MachicolationLayout.Collect` puts one `MachicolationSpot` on each outward face (`BattlementRules.Faces`) of every gate cell, at the edge middle (a crenel) `MachicolationSettings.standInset` (0.85m) inside the face, on the column's top surface. `Walls/GateMachicolations` (on the `ConstructionWorld` object, rebuilt on `Changed` and when a column piece's `IsUnderConstruction` flips) creates a `Combat/ShotOpening` per spot under a `Machicolations` child, with the gate column's pieces as exempt colliders, the `MachicolationShaft` box and the settings' attack modules, plus a collider-free `Visual` (overhang + dark hole marker, `NavMeshModifier.ignoreFromBuild`). `ShotOpening.At(attacker)` (same team, a module's `CanUse`, feet within `standRadius` 0.6m) feeds `CombatPhysics.TryGetShotPoint` (`PassesOpening`: exempt collider with entry and exit inside the shaft) and `CombatProjectile.ShouldIgnore` (contact inside the shaft). Attack methods are `Combat/MachicolationAttack` ScriptableObject modules; only `ArrowMachicolationAttack` (ranged attackers) exists. `UnitCombatAI.UpdateOpening` / `ClaimOpening`: an allied ranged unit in `Hold` with no target ranks openings with `MachicolationRules.Rank` (free, same level, within `searchRadius` 12m of the post, enemy below via `ShotOpening.HasEnemyBelow`), takes the nearest with a complete path that stays above `HoldMaxDescent`, stands on it and returns to the post when nothing is left below (`ShouldRelease`). `ShotOpening.IsFreeFor` also refuses a spot someone else (the player included) stands on. Assets: `Data/GameFlow/Build/Machicolations.asset`, `MachicolationArrow.asset`, `Art/Placeholder/MachicolationHole.mat`, created by `Editor/MachicolationSetup` (menu `ProjectNeo/Setup/Add Machicolations To Game Scene`). Game scene, plus the verification scene `Scenes/MachicolationVerification.unity` from `Editor/MachicolationVerificationSetup` ([PrototypeScenes](PrototypeScenes.md)). Tests: EditMode `MachicolationRulesTests`, PlayMode `MachicolationPlayTests`.

Auto battlements (`SIEGE-10`, `feature/siege-10`): pure `Walls/BattlementRules` (`CollectOutside` flood fill from the grid edge over empty columns; `Faces` bitmask N/E/S/W for a cell's top Wall/Gate piece — closed toward same-or-higher neighbours and non-outside cells; `Segments` for `BattlementStyle` Parapet=1 / Crenellated=2; a continuous sill plus merlons placed so every edge middle is a crenel) and `BattlementSettings` (asset `Data/GameFlow/Build/Battlements.asset`). `Walls/CastleBattlements` on the `ConstructionWorld` object rebuilds a `Battlement` child under each top piece on `ConstructionWorld.Changed`, on style change and when `IsUnderConstruction` flips (none while under construction); parts are `BoxCollider` + `Combat/ShotCover` (passable for `Allied`) with a `Visual` cube child, so they move and vanish with the piece and NavMesh treats them as walls. The outside set is recomputed only when `ConstructionWorld.LayoutRevision` changes (prep place/dismantle/restore) and when `Flow/GameBattlements` sees the phase enter Preparation (`CastleBattlements.RecomputeOutside`), so faces stay fixed during battle. `BattlementRules.CollectEnclosed` derives the start footprint from `ConstructionWorld.InitialPieces` (every cell the start layout keeps unreachable from the grid edge: ring cells and courtyard); the `CollectOutside(..., alwaysInside)` overload never floods into it, so a gapped default ring gets neither inner-face nor gap-end battlements (`BUG-battlement-inner-faces`). `SiegeLadder.EdgePoint` rises by `CastleBattlements.SillHeightAt(cell, outward)` so the ladder top rests on the crenel sill (no gap). Since SIEGE-11 only the face a mounted weapon points at (`MountLayout.FacingFaces`: piece rotation + mount point yaw + weapon R rotation) uses Parapet instead of Crenellated (`GunPortFaces`, `StyleFor(placement, face)`, `IsGunPortAt(cell)` / `IsGunPortAt(cell, face)`); crenel stand points skip only that face. `CombatPhysics.TryGetShotPoint` (used by `HasClearShot` and by `CharacterActor` projectile aiming) tries `AimPoint`, then the upper body (`CombatProfile.UpperAimRatio`); `HasClearShotFrom(standPoint, ...)` checks a hypothetical spot. `SiegeAttackerBrain.DecideArcher` side-steps through the pure `Siege/ArcherCoverPlan` (in-range blocked delay, one search per cooldown, spot commit, wait in place; EditMode `ArcherCoverPlanTests`) with `TryFindFiringPosition` / `CanShootFrom`, and exposes `IsArcherFiring` / `IsArcherRepositioning` / `IsArcherWaiting` for animation. `ShotCover.Passes` is checked by `CombatPhysics.HasClearShot`, `CombatProjectile`, `CannonShell` and the `CannonOperator` aim ray. `Flow/GameBattlements` applies `FacilityLevel.battlementStyle` of the Defense facility (Lv1 Parapet, Lv2 Crenellated) every frame and drives the build-panel `Button_Battlements` (`TryUpgrade`: preparation only, `RunState.TryUpgradeFacility`); the Defense facility window text (`GameFacilities.DescribeDefense`) is ready but the facility still has no station of its own. Setup menu `ProjectNeo/Setup/Add Battlements To Game Scene` (`Editor/BattlementSetup`). Game scene only; prototype scenes have none. COMBAT-08: `Walls/BattlementRules.WalkwayWidth` (wall-top walkway width along an axis-aligned direction within 30 degrees, wall top only, minus battlement thickness on faces that have battlements) and `CastleBattlements.WalkwayWidthAt` feed the squad drag-line cap (`SquadCommandCenter.WalkwayWidth`, wired by `GamePrepPlacement`). COMBAT-10: `BattlementRules.CrenelCenters` (pure crenel centres along an edge, Crenellated style) and `CastleBattlements.CollectCrenelStandPoints` (stand points 0.45m inside each crenel; skips gun ports, pieces under construction and corner end crenels) feed `CrenelSlotRules` through `GamePrepPlacement`. Parapet sill raised to 1.1m for Lv1 and Lv2 (`BattlementSettings.parapetHeight`). [History](../history/COMBAT/COMBAT-10.md).

Gate door-only destruction (`SIEGE-06`, `feature/siege-06`): `Editor/ConstructionGateArchMesh` generates `Art/Placeholder/ConstructionGateArch.asset`, and `MainGate.prefab` splits `Visual/StoneArch` (`ConstructionStone.mat`) + three arch `BoxCollider`s from `Visual/Door` (`ConstructionGate.mat`) + `doorCollider` wired to `PlacedStructure`. Mixed enemy composition (`B-6.4`, `feature/b-6.4`): `Editor/EnemyCompositionVerificationSetup` creates `Scenes/EnemyCompositionVerification.unity` with a separate 5-enemy roster (2 ladder, 1 wall breaker, 1 melee flyer, 1 high projectile flyer). The high variant combines existing flight modules, higher hover data and the existing archer profile/definition; no additional runtime behavior class. `SiegeDirector` passes scene settings into `SiegeAttacker.Bind` for both ground/flying spawns. Shared ladders (`SIEGE-04`, `feature/siege-04`): pure `Siege/LadderTraffic<T>` enforces FIFO single occupancy for both directions and teams, and tracks approach-time reservations (`Reserve`/`Unreserve`/`Approaching`/`PlannedLoad`, `BUG-ai-core-defects`) disjoint from `Occupant` and `Waiting`. `SiegeLadder` keeps legacy enemy raising/climbing APIs while routing their occupancy through the shared actor queue; it also handles allied raising, friendly-use automatic-topple protection (still based strictly on `Occupant`/`Waiting`), and `PlannedCrowdExcluding` approach load reporting. `Siege/LadderTraveller` is added at runtime by allied `UnitCombatAI` or `PlayerInputController`, without prefab/scene edits. It selects a reachable ladder route only when the ordered destination lacks a complete walking path, reserves its chosen ladder immediately upon selection (`AssignedLadder`) so squads split across multiple ladders before reaching the base (`BUG-ai-core-defects`), drives approach/ascent/descent, defers orders received aboard, and restores NavMeshAgent/CharacterController or hands interruption/death to `UnitFallController`. Player uses tap F boarding, W/S climbing and hold F raising/toppling; `SiegeSettings.LadderTapSeconds` controls the temporary 0.25s tap threshold. `CharacterActor.IsOnLadder` prevents new attacks and cancels pending impacts while remaining damageable. GameFlowHud/SiegeStatusHud show contextual traversal hints. [Verification](../history/SIEGE/SIEGE-04.md).

One-cell stairs (`SIEGE-03`): shared `Data/ConstructionPrototype/Stairs.asset` uses a 1×1 footprint and 3m height. `ConstructionWorld.SetPose` scales the existing normalized ramp collider and Visual to 3×3×3m; no mesh or material change is needed for size. The ramp mesh (`Art/Placeholder/ConstructionRamp.asset`) is generated by `Editor/ConstructionRampMesh` with per-face vertices for flat shading (`ART-01`; menu `ProjectNeo/Setup/Flatten Stair Shading` rewrites it in place). `Editor/OneCellStairsMigration` retains high landings while moving initial seeds in ConstructionPrototype, WallCommandPrototype, SiegePrototype and Game (7 stairs total); repeated execution does not move them again. Setup generators now emit the new locations. Humanoid NavMesh maximum slope is 46° to admit the exact 45° ramp; `Characters/PlayerControlSettings.MaximumWalkSlope` defaults to 46° and is applied by PlayerInputController.Awake. Four Game PlayMode cases cover both traversal directions, rotations, two tiers and disconnection after stair destruction. Since `SIEGE-18` the shared `Stairs.asset` is 5m high and uses `Prefabs/ConstructionPrototype/StairsNarrow.prefab` (5m wide, centred on 7.5m cells). [History](../history/SIEGE/SIEGE-03.md).

Construction wheel input (`BUG-build-camera-zoom`): ConstructionCameraController uses normalized scroll steps directly; only Windows editor/player with KeepPlatformSpecificInputRange divides by 120. GameFlowPlayTests.ConstructionWheelInput_UsesNormalizedStepsAndRestoresCamera covers actual input → Update → zoom/reset; user confirmed physical wheel zoom works (2026-11-13). [History](../history/BUG/BUG-build-camera-zoom.md).

Grid display (`BUG-build-grid-lines`): BuildCameraSettings.MinimumGridLinePixels (default 1.5px) is exposed through ConstructionCameraController. BuildGridView updates its cached mesh before each URP Game camera render, computing perpendicular pixel widths separately for the two grid axes; original world line width remains the minimum. Cell centers/spacing, occupancy and picking stay unchanged. Cameras without an orthographic construction controller use original width. [History](../history/BUG/BUG-build-grid-lines.md).
