# Runtime Codemap: Core, Stats, Characters, Combat & Squads

Last Updated: 2026-11-13 19:42:56 (KST)

> Purpose: Class map for core utilities, stats, characters, combat AI, squads, and morale. | Parent: [codemap/README](README.md) | Related: [WallsAndSiege](WallsAndSiege.md), [design/Combat](../design/Combat.md)

Base path: `Assets/_Project/Scripts/Runtime/`. Assembly: `ProjectNeo.Runtime`. Namespace: `ProjectNeo.<Folder>`.

| Folder | Key Classes | Role |
|---|---|---|
| Core | `RandomSource`, `WeightedPool`, `Unlockable` | Seed-based random generator, weighted selection pool, common unlock types and interfaces. |
| Stats | `StatSheet`, `StatValue`, `StatModifier`, `StatType` | Base stats and source-specific modifiers: `(base + flat) * (1 + percent)`. |
| Characters | `HeroDefinition`, `SoldierDefinition`, `SkillDefinition`, `Character` | Hero/grunt/skill data. `Character` stores individual hero stats and equipment; player uses same class. |
| Characters | `PlayerControlSettings`, `PlayerInputController` | Control/camera settings asset, Input System bindings, and CharacterController movement. FirstPersonCamera is default. |
| Characters | `PlayerViewCamera`, `FirstPersonCamera` | Common camera interface and default 1st-person camera driven by `PlayerControlSettings`. Player visual casts shadow only while active. ThirdPersonCamera preserved unused. |
| Combat | `Health` | Pure C# health rules. Damage, death, max HP scaling, `RestoreFull` for living units (no resurrecting dead). Stat subscriptions unsubscribed via `Dispose()`. `CharacterActor.SoldierDefinition` reads grunt data. |
| Combat | `CombatProfile`, `CharacterActor`, `CombatTeam` | Body size, attack type, windup delay, min damage, projectile settings asset. Bridges heroes and grunts to common stats; handles teams, targeting, melee/ranged attacks, cooldowns, hit reactions, death. `Character` attached to heroes only; common access uses `Stats`. |
| Combat | `DamageRules`, `CombatPhysics` | Pure C# damage formulas, range, and line-of-sight checks. Attacks enemies in scene; allies do not occlude. Ranged attacks not blocked by shooter's ground object (`GroundUnder`). LoS checks and projectiles share identical rules. |
| Combat | `CombatProjectile` | Linear projectile. Stores damage, team, and direction upon launch; applies defense on hit. Passes through allies, hits first enemy or wall, terminates at max range or lifetime. |
| Combat | `UnitAISettings`, `UnitCombatAI` | Search radius, tick interval, rotation, movement, arrival thresholds. Picks closest reachable enemy, updates NavMesh path, melee/ranged attacks, stops on death. Empty-target Hold/Engage searches respect `DecisionInterval`; existing invalid targets drop immediately. Hold attack candidates use conservative collider AABB bounds before exact range/LoS; retained valid Engage targets reuse reachability path. Directives: `Engage`, `Hold` (melee advances within `HoldEngageRadius` 6m; ranged within attack range + `HoldRangedChaseExtra` 6m; return beyond `HoldReturnDistance` 1m), `Move`. Arrival: remaining <= `ArrivalDistance` (0.35m) or `MoveStallTracker` (`MoveStallProgress` 0.1m over `MoveStallSeconds` 0.5s within `MoveStallDistance` 1.5m). Move/Engage advance clears a rejected valid path and retries calculation/application once on the next AI update during NavMesh replacement; a second rejection or no route ends advance normally. New directives clear the retry flag. Default without orders: Engage. |
| Combat | `PlaceholderCombatView` | Subscribes to attack, damage, and death events under `Visual` child. Placeholder tinting, attack telegraphs, health bar, death visuals. Contains no combat logic. |
| Squads | `SquadConfig`, `Squad<TUnit>`, `Army<TUnit>` | Squad and army member caps, captain assignments. `Squad.Morale` (Q-44) holds the squad's `SquadMorale` between battles; null until first used (then 150). |
| Squads | `SquadCommander`, `SquadOrder`, `SquadFormation` | Pure C# squad command logic. Single/all selection, Move/Attack/Hold orders, default Hold state, arrival transition to Hold, rank-and-file formation offsets. Decoupled from scene and input. |
| Squads | `SquadCommandSettings`, `SquadCommandCenter`, `SquadCommandInput` | Command hotkeys (`InputAction`), formation settings asset (`Command.asset`), translates orders to `UnitDirective` and formation slots, tracks arrival, screen-center raycast. D-0b: `SquadCommandCenter.AddSquad`/`AddMember`/`TryGetGatherPoint` and `SquadCommander.AddSquad` grow squads at runtime; B-8.2 `Detach`/`Reattach`/`IsDetached` exclude routing members from orders, formation, arrival and gather point while `AliveCount` still counts them; `PlaceholderSquadMarkers` creates discs lazily. |
| UI | `SquadCommandHud` | Test command overlay (selection, orders, headcount, prompts, reticle). Not final HUD. |
| Morale | `SquadMorale` | Squad morale value (0–max) carried with the squad across battles; perks change it via `Add`. |
| Morale | `MoraleSettings`, `MoraleTypes` (`MoraleSide`, `MoraleState`, `CollapseEffect`, `AwakenEffect`) | Morale tuning asset (Q-04/Q-38/Q-39/Q-44 starting values, `Create()` for tests) and state enums. Instance `Data/GameFlow/Morale.asset` (full-squad loss ≈166.7 = 150 → 0 at 90% deaths; rout movement `RetreatInset` 9m, `RetreatArrivalDistance` 2.5m, `RetreatTimeout` 20s), linked from `Battle.asset` by `Editor/MoraleSetup`. `MoraleSide.Enemy` unused since Q-44 (enemies have no morale). |
| Morale | `GameSquadMorale` | B-8.2 Game-scene wiring, added at runtime by `GameBattleController.Awake` when `GameBattleSettings.Morale` is set (no scene edit). Subscribes to `GameFlow.PhaseChanged`: Battle → one `BattleSquadMorale` per ally squad with living members (member/captain `Died`, last-gate `PieceCollapsing`, nearby wall collapse once per squad per frame, nearby rout, `NearbyMoraleChange` within `NearbyRadius` = any living member in range); Reward/RunResult → dispose + `RecoverAfterBattle`; Preparation → exited units reappear at `RetreatPoint` and walk to their squad gather point. Routed units are `SquadCommandCenter.Detach`ed, Move to `RetreatPoint` (castle-structure bounds, edge opposite `Outward`, inset), exit (SetActive false) on arrival or timeout. `HasFled` feeds `BattleResult` `Fled`. Morale stored on run squad `Squad<RunUnit>.Morale` (scene squad fallback). Collapse/Awaken combat effects and HUD: COMBAT-01. |
| Morale | `BattleSquadMorale`, `MoraleRules` | B-8.1 pure C# rules. Per-battle wrapper over `SquadMorale`: loss events (member/captain death, gate, nearby wall, nearby rout), once-per-battle breaking point at 100 (Collapse Fear/Panic/Contagion or 25% Awaken Rally/Last Stand/Steadfast), start-below-100 weak collapse, rout at 0 (Steadfast exempt), `AttackMultiplier`, `ShouldIgnoreOrder`, `Tick` for Panic/Contagion. Raises `BreakingPointReached`, `Routed`, `NearbyMoraleChange`, `PanicRetreat`; scene applies nearby effects. `MoraleRules.RecoverAfterBattle` = max(+20, 80) capped. `SquadMorale` treats values below 0.001 as 0 so proportional losses reach exactly 0. Wired in Game by `GameSquadMorale` (B-8.2); `AttackMultiplier`/`ShouldIgnoreOrder`/`Tick` not yet applied (COMBAT-01). |
