# Runtime Codemap: Core, Stats, Characters, Combat & Squads

Last Updated: 2026-11-17 15:54:43 (KST)

> Purpose: Class map for core utilities, stats, characters, combat AI, squads, and morale. | Parent: [codemap/README](README.md) | Related: [WallsAndSiege](WallsAndSiege.md), [design/Combat](../design/Combat.md)

Base path: `Assets/_Project/Scripts/Runtime/`. Assembly: `ProjectNeo.Runtime`. Namespace: `ProjectNeo.<Folder>`.

| Folder | Key Classes | Role |
|---|---|---|
| Core | `RandomSource`, `WeightedPool`, `Unlockable` | Seed-based random generator, weighted selection pool, common unlock types and interfaces. |
| Stats | `StatSheet`, `StatValue`, `StatModifier`, `StatType` | Base stats and source-specific modifiers: `(base + flat) * (1 + percent)`. |
| Characters | `HeroDefinition`, `SoldierDefinition`, `SkillDefinition`, `Character` | Hero/grunt/skill data. `Character` stores individual hero stats and equipment; player uses same class. |
| Characters | `PlayerControlSettings`, `PlayerInputController`, `PlayerLocomotionRules` | Control/camera settings, runtime-copy Input System bindings, CharacterController movement. Hold either Ctrl to crouch (50% speed, 60% capsule/eye height, feet fixed); hold either Shift to sprint (150%); Space jumps 1.2m with 30% air control, blocked while crouched/suspended/airborne (COMBAT-05, `TryJump`, `IsJumping`, `PlayerLocomotionRules.JumpSpeed/AirHorizontal/CanJump`). Crouch wins; overhead solids defer standing. Movement suspension blocks locomotion; sprint clears on suspension, disable and focus loss. FirstPersonCamera is default. BUG-popup-cursor: capture on enable and gameplay focus return; ignore Escape during the capture frame so closing a modal cannot immediately release the cursor. Disabled player input leaves UI cursor state unchanged. |
| Characters | `PlayerViewCamera`, `FirstPersonCamera` | Common camera interface and default 1st-person camera driven by `PlayerControlSettings`. Player visual casts shadow only while active. ThirdPersonCamera preserved unused. |
| Combat | `Health` | Pure C# health rules. Damage, death, max HP scaling, `RestoreFull` for living units (no resurrecting dead). Stat subscriptions unsubscribed via `Dispose()`. `CharacterActor.SoldierDefinition` reads grunt data. |
| Combat | `CombatProfile`, `CharacterActor`, `CombatTeam`, `ActionPoise`, `IInterruptibleAction`, `ActionInterruptRules` | Body size, attack type, windup delay, min damage, `StaggerPower`, projectile settings asset. Bridges heroes and grunts to common stats; handles teams, targeting, melee/ranged attacks, cooldowns, hit reactions, death, and single-hit poise vs stagger action interruption (`RegisterInterruptible`/`UnregisterInterruptible`, `ActionInterrupted`, COMBAT-04). `Character` attached to heroes only; common access uses `Stats`. |
| Combat | `DamageRules`, `CombatPhysics` | Pure C# damage formulas, range, and line-of-sight checks. Attacks enemies in scene; allies do not occlude. Ranged attacks not blocked by shooter's ground object (`GroundUnder`). LoS checks and projectiles share identical rules. |
| Combat | `RangeRules`, `CombatPhysics.AttackRange` / `MaximumAttackRange` (`BUG-wall-archer-los`) | Pure high-ground range multiplier and arrow flight distance. `CombatPhysics.AttackRange(attacker, target)` applies `CombatProfile.HighGroundRangeBonus` (0.25) when a grounded projectile attacker stands `HighGroundMinimumDrop` (1.5m) or more above the target; `IsInRange` uses it, `UnitCombatAI.FindTargetInReach` pre-filters with `MaximumAttackRange`, and `CharacterActor.ResolveImpact` launches arrows with `RangeRules.FlightDistance`. Existing profile assets use the code defaults. Tests: EditMode `RangeRulesTests`, PlayMode `WallTopArcherPlayTests`. [History](../history/BUG/BUG-wall-archer-los.md). |
| Combat | `AirborneBody`, `AirborneReach` (`B-6.3`) | Airborne target state (ground projection, melee exposure) cached on `CharacterActor.Airborne`. `CombatPhysics.IsInRange` measures melee vs airborne from attacker feet to projection only while exposed; `ReachPoint` gives the projection for `UnitCombatAI` paths; `CanTarget` keeps melee units from choosing high flyers. `CombatProjectile` skips the upward-shot ratio for airborne targets. |
| Combat | `CombatProjectile` | Linear projectile. Stores damage, team, and direction upon launch; applies defense on hit. Passes through allies, hits first enemy or wall, terminates at max range or lifetime. |
| Combat | `UnitAISettings`, `UnitCombatAI` | Search radius, tick interval, rotation, movement, arrival thresholds. Picks closest reachable enemy, updates NavMesh path, melee/ranged attacks, stops on death. Empty-target Hold/Engage searches respect `DecisionInterval`; existing invalid targets drop immediately. Hold attack candidates use conservative collider AABB bounds before exact range/LoS; retained valid Engage targets reuse reachability path. Directives: `Engage`, `Hold` (melee advances within `HoldEngageRadius` 6m; ranged within attack range + `HoldRangedChaseExtra` 6m; return beyond `HoldReturnDistance` 1m), `Move`. Arrival: remaining <= `ArrivalDistance` (0.35m) or `MoveStallTracker` (`MoveStallProgress` 0.1m over `MoveStallSeconds` 0.5s within `MoveStallDistance` 1.5m). Move/Engage advance clears a rejected valid path and retries calculation/application once on the next AI update during NavMesh replacement; a second rejection or no route ends advance normally. New directives clear the retry flag. Default without orders: Engage. |
| Combat | `PlaceholderCombatView` | Subscribes to attack, damage, and death events under `Visual` child. Placeholder tinting, attack telegraphs, health bar, death visuals. With a `Model` assigned (ART-03) it tints all model renderers (hit = brighten, dead = dark) and lays the model down on death instead of squashing `Body`. Contains no combat logic. |
| Combat | `CharacterModelAnimator` | View-only (ART-03): feeds horizontal speed to the model Animator float `Speed` (idle/walk/run blend; flyers loop an in-air clip) and freezes the Animator on death. No attack/hit/death clips yet. |
| Squads | `SquadConfig`, `Squad<TUnit>`, `Army<TUnit>` | Squad and army member caps, captain assignments. `Squad.Morale` (Q-44) holds the squad's `SquadMorale` between battles; null until first used (then 150). |
| Squads | `SquadCommander`, `SquadOrder`, `SquadFormation` | Pure C# squad command logic. Single/all selection, Move/Attack/Hold orders, default Hold state, arrival transition to Hold, rank-and-file formation offsets. Decoupled from scene and input. COMBAT-03 `OrderRequested` filters each selected squad once before changing its order; arrival completion bypasses the filter. D-8: `RemoveSquad` shifts later orders/selection (`SquadRemoved`). |
| Squads | `SquadCommandSettings`, `SquadCommandCenter`, `SquadCommandInput` | Command hotkeys (`InputAction`), formation settings asset (`Command.asset`), translates orders to `UnitDirective` and formation slots, tracks arrival, screen-center raycast. D-0b: `SquadCommandCenter.AddSquad`/`AddMember`/`TryGetGatherPoint` and `SquadCommander.AddSquad` grow squads at runtime; B-8.2 `Detach`/`Reattach`/`IsDetached` exclude routing members from orders, formation, arrival and gather point while `AliveCount` still counts them; `PlaceholderSquadMarkers` creates discs lazily. D-8: `MoveMember` (drops dead bodies from a full target first), `RemoveSquad` (no living members; shifts indices), `SetLeader`. D-3: the squad leader (hired captain) also follows squad orders at the front of the formation. C-3: `RemoveFallen` drops dead members and dead leaders from scene squads (bodies stay); `PlaceholderSquadMarkers` only reads current squad indices and hides leftover destination discs after squad removal. |
| UI | `SquadCommandHud` | Test command overlay (selection, orders, headcount, prompts, reticle). COMBAT-03 adds allied morale/state and latest one-line notice to its existing TMP label when GameSquadMorale exists. Not final HUD. |
| Morale | `SquadMorale` | Squad morale value (0–max) carried with the squad across battles; perks change it via `Add`. |
| Morale | `MoraleSettings`, `MoraleTypes` (`MoraleSide`, `MoraleState`, `CollapseEffect`, `AwakenEffect`) | Morale tuning asset (Q-04/Q-38/Q-39/Q-44 starting values, `Create()` for tests) and state enums. Instance `Data/GameFlow/Morale.asset` (full-squad loss ≈166.7 = 150 → 0 at 90% deaths; rout movement `RetreatInset` 9m, `RetreatArrivalDistance` 2.5m, `RetreatTimeout` 20s), linked from `Battle.asset` by `Editor/MoraleSetup`. `MoraleSide.Enemy` unused since Q-44 (enemies have no morale). |
| Morale | `GameSquadMorale` | B-8.2 Game-scene wiring, added at runtime by `GameBattleController.Awake` when `GameBattleSettings.Morale` is set (no scene edit). Subscribes to `GameFlow.PhaseChanged`: Battle → one `BattleSquadMorale` per ally squad with living members (member/captain `Died`, last-gate `PieceCollapsing`, nearby wall collapse once per squad per frame, nearby rout, `NearbyMoraleChange` within `NearbyRadius` = any living member in range); Reward/RunResult → dispose + `RecoverAfterBattle`; Preparation → exited units reappear at `RetreatPoint` and walk to their squad gather point. Routed units are `SquadCommandCenter.Detach`ed, Move to `RetreatPoint` (castle-structure bounds, edge opposite `Outward`, inset), exit (SetActive false) on arrival or timeout. `HasFled` feeds `BattleResult` `Fled`. Morale stored on run squad `Squad<RunUnit>.Morale` (scene squad fallback). COMBAT-03 applies source-owned Attack modifiers, ticks Panic/Contagion, vetoes Fear orders through `SquadCommander.OrderRequested`, and exposes HUD states/notices. Panic uses runtime `PanicRetreatPoint` at the courtyard retreat location, detaches members/captains until battle end, and holds without exiting or recording Fled; morale-0 rout still takes priority. Modifiers/hooks/transient Panic state are cleared on end/disable/destruction. Captain-only squads receive morale wrappers. [History/manual checks](../history/COMBAT/COMBAT-03.md). |
| Morale | `BattleSquadMorale`, `MoraleRules` | B-8.1 pure C# rules. Per-battle wrapper over `SquadMorale`: loss events (member/captain death, gate, nearby wall, nearby rout), once-per-battle breaking point at 100 (Collapse Fear/Panic/Contagion or 25% Awaken Rally/Last Stand/Steadfast), start-below-100 weak collapse, rout at 0 (Steadfast exempt), `AttackMultiplier`, `ShouldIgnoreOrder`, `Tick` for Panic/Contagion. Raises `BreakingPointReached`, `Routed`, `NearbyMoraleChange`, `PanicRetreat`; scene applies nearby effects. `MoraleRules.RecoverAfterBattle` = max(+20, 80) capped. `SquadMorale` treats values below 0.001 as 0 so proportional losses reach exactly 0. Wired in Game by `GameSquadMorale` (B-8.2); `AttackMultiplier`/`ShouldIgnoreOrder`/`Tick` are applied by GameSquadMorale (COMBAT-03). |

- **User-approved crouch view refinement (2026-11-13)**: First-person eye height transitions with SmoothStep over 0.18 seconds (PlayerControlSettings.CrouchViewTransitionSeconds); capsule changes remain immediate. Reversing Ctrl mid-transition continues from the currently displayed height. Root movement/falls follow immediately; camera re-enable resets the transition.
