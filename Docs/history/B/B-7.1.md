## Background

The `Game` scene spawned one fixed enemy list regardless of stage number, all at battle start, from one spawn cell. Q-51 (2026-11-14) fixed the structure (3 stages, 2–3 timed waves, fixed northern spawn points). On 2026-11-16 the user asked for a format that is as decoupled and changeable as possible and started implementation; teammate review of the format continues in parallel.

## Decisions (Q-52, user, 2026-11-16)

| Item | Choice |
|---|---|
| Wave start | Fixed timetable kept; an empty field does not pull the next wave forward. The start condition is a replaceable rule. |
| Retreat while waves remain | Settings switch (`GameBattleSettings.RetreatWhileWavesPending`), default off: no Q-30 retreat until every wave is out. |
| Past the last stage | Interim: the last stage repeats until the run ending (Q-08) exists. |

## Implemented scope

Four layers, each replaceable alone:

1. **Timetable rule (pure C#, `Runtime/Stages/WaveSchedule.cs`)**: `WaveTiming`, `WaveStartContext`, `IWaveStartRule`, `TimedWaveStartRule` (default), `WaveSchedule` (`Advance`, `Reset`, `PendingWaves`, `PendingUnits`, `SecondsUntilNext`, static `RetreatAllowed`). No prefab, scene or Unity-time knowledge; time only moves by the delta passed in.
2. **Stage data (assets)**: `SpawnPointDefinition` (named build-grid cell), `StageWaveGroup` / `StageWave` (serializable structs), `StageDefinition`, `StageCatalog` (`StageFor(stageNumber)`, clamps to the last stage). All have `Create(...)` factories.
3. **Encounter plan (plain data, `EncounterPlan` / `EncounterWave` / `EncounterGroup`)**: the only shape the battle reads. `FromStage` resolves spawn points and drops empty entries; `FromGroups` wraps the old single enemy list as one wave at 0s.
4. **Scene**: `Flow/BattleEnemySpawner` (plain class) instantiates one wave in formation per spawn cell; `GameBattleController` pre-creates every wave inactive in preparation and activates a wave when the schedule releases it.

`GameBattleController` additions: `Plan`, `WaveCount`, `WavesReleased`, `SecondsUntilNextWave`, `EnemiesOnField`, `EnemiesPending`, `WaveReleased` event, `RebuildEncounter()`, static `DefaultEncounter` / `SingleWaveEncounter`, and static `EncounterSourceOverride` (swap how the encounter is chosen: debug rosters, tests, future modifiers). `EnemiesAlive` keeps its meaning (field + pending). `Enemies` still lists every enemy of the battle.

Behaviour changes:

- Victory uses `SiegeOutcomeRules.Evaluate(..., EnemiesOnField, EnemiesPending)`, so an empty field with waves to come is not a victory. This is the core of `SIEGE-01`; that task keeps only its own verification scope.
- Retreat (Q-30) is judged only among enemies that are on the field and not already leaving; a newly released wave re-opens the judgement while enemies already leaving keep leaving.
- `CountRetreats` no longer casts to `SiegeAttackerBrain`; a retreating flyer would have thrown before (flyers now appear in Stage 3).
- `GameFlowHud` battle status shows `웨이브 N/M · 다음 Ns` only when the battle has more than one wave.

Data (created through `Editor/StageSetup`, menu `ProjectNeo/Setup/Create Stage Data (B-7.1)`, idempotent, no scene edit): `Data/GameFlow/Stages/SpawnLeft|SpawnCenter|SpawnRight.asset` (cells 25 / 40 / 55, row 90), `Stage01–03.asset`, `StageCatalog.asset`; `Battle.asset` gained the catalog reference. The old enemy list in `Battle.asset` is kept as the fallback.

## Manual check

1. Open `Assets/_Project/Scenes/Game.unity`, press Play, start a run from the scene (or from `Title`).
2. Hold B for 1 second. Expected: 6 enemies (4 ladder, 2 archer) come from the north center; the battle status shows `남은 적 12` and `웨이브 1/2 · 다음 40초` counting down.
3. Kill the first wave before the timer ends. Expected: the battle does not end; the timer keeps counting.
4. At 40 seconds. Expected: 6 more enemies appear at once — ladder troops on the left, gate breakers in the center, archers on the right — and the line reads `웨이브 2/2 · 마지막`.
5. Kill everything. Expected: victory and reward exactly once. `Claim Reward & Next Stage`.
6. Stage 2 and Stage 3. Expected: three waves each (40s/80s and 35s/70s), wall breakers from Stage 2, flyers from Stage 3; the same stage always brings the same waves.
7. Optional: in `Data/GameFlow/Battle.asset` tick `Retreat While Waves Pending` and leave only archers alive in wave 1 with the walls closed. Expected: they walk off north before wave 2. Untick it afterwards.
8. To change a stage: edit `Data/GameFlow/Stages/Stage0N.asset` (times, counts, prefabs, spawn points) or add a `Spawn Point` asset; no code change is needed.
9. Reset: stop Play mode. Nothing is written to the scene.
