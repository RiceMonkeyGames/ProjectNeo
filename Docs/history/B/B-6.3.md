## Scope and decisions

Branch `feature/b-6.3`, claimed by Claude in develop commit `f381982`. Implements the Q-43 flyer contract. Backlog listed this as enemy-assault (teammate) scope; the user took it on 2026-11-13 and gave these decisions the same day:

- **Shared combat code**: Edits to `CombatPhysics`, `UnitCombatAI`, `CharacterActor` and `CombatProjectile` approved, limited to airborne-target branches.
- **Structure**: "Choose a good structure for later extension regardless of size." Agent chose a shared `SiegeAttacker` base for walking and flying enemies, with flight split into data-selected modules.
- **Hover height**: Must stay flexible for future variants — flyers that melee can reach and flyers that must be shot down. Implemented as data: engagement hover height plus a flyer melee-exposure altitude.
- **Wall-top ally**: An ally standing at least 1m above world ground (same rule as cannon targeting).

Agent defaults (not separately asked; recorded for review): a flyer with no target holds at cruise height over the castle-piece centroid moved `HoldInset` (6m) inward, since SiegePrototype has a single wall line and the raw centroid lies on the wall. Cruise height = tallest castle piece top + `CruiseClearance` (3m). Dead flyers drop to the surface below with no fall damage. Flyers do not get `UnitFallController`.

## Implementation

- `Siege/SiegeAttacker` (abstract): common contract for SiegeDirector/GameBattleController (Role, HasDecided, IsAssaulting, IsRetreating, Fled, IsMidAction, UsesFallController, Bind, Retreat, CanReachAnyEnemy, BeginExit). `SiegeAttackerBrain` now derives from it; its ladder/gate/archer/wall-breaker behavior is unchanged. The controller's NavMesh-specific retreat check/exit moved into `SiegeAttackerBrain.CanReachAnyEnemy/IsMidAction/BeginExit`. `SiegeAttackerRole.Flyer = 4` appended.
- `Siege/FlyerBrain`: no NavMeshAgent/UnitCombatAI. Re-decides every `AttackerDecisionInterval`; target death triggers immediate re-selection; flies with the movement module, hovers at the engagement point and attacks through `CharacterActor.TryAttack` (existing cadence, impact delay, melee/projectile). Retreat flies to the outward map edge at cruise height and flees; controller-driven exit flies to the given exit.
- Modules (ScriptableObjects, selected in `FlyerSettings`): `FlyerTargetStrategy` → `WallTopFirstFlyerTargetStrategy`; `FlyerMovement` → `DirectFlightMovement` (climb to cruise, cross, descend near destination); `FlyerEngagement` → `HoverBesideEngagement` (beside target at hover height, prefers a spot on the target's own surface). A high-hover ranged variant = same modules with a projectile CombatProfile and a higher hover height.
- `Combat/AirborneBody` + `AirborneReach`: flyer publishes ground projection and melee exposure each frame. `CombatPhysics.IsInRange` measures melee range from attacker feet to the projection only while exposed; `ReachPoint` gives the projection for ally path finding; `CanTarget` stops melee allies from choosing high flyers. `CombatProjectile` skips the upward penalty for airborne targets (allies already use ratio 1; this keeps it true for future profiles).
- Editor `FlyerSetup.CreateAssets`, menu `ProjectNeo/Setup/Add Flyer Assets`: clones `enemy_ladder` into `Prefabs/SiegePrototype/enemy_flyer.prefab` (brain/AI/agent/fall removed, AirborneBody + FlyerBrain added, placeholder wing marker), creates `Data/SiegePrototype/Flyer.asset`, `FlyerTargetWallTopFirst.asset`, `FlyerDirectFlight.asset`, `FlyerHoverBeside.asset`, and registers the flyer in the SiegePrototype roster at **0**. Re-running keeps existing assets/counts. Game scene encounters unchanged (B-6.4/B-7.1).
- Tests updated for the base type (`SiegeAttacker`, `OfType<SiegeAttackerBrain>()` for climbing checks; prefab role lookups null-safe).
