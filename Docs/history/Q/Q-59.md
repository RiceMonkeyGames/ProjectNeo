# Q-59 | 2026-11-23 | Building Tier Limits & Edge Cases

> Purpose: Decision log. | Parent: [history/README](../README.md) | Related: [Decisions-Resolved](../../plan/Decisions-Resolved.md), [Walls & Siege design](../../design/WallsAndSiege.md), [SIEGE-14](../SIEGE/SIEGE-14.md)

- Branch `feature/q-59`; youngho. Doc-only decision task; no game code, scenes or assets changed.
- Input: the [SIEGE-14](../SIEGE/SIEGE-14.md) spike already settled the valley rule, collapse of upper storeys, automatic stairs, stairs behind a breach and tower stacking for the kit. Open for the Game on 5m tiers: the maximum number of tiers, the default wall height and whether the valley rule is on.

## Options presented

1. Maximum height: (A) walls and bastions 2 storeys, towers 3 (recommended); (B) everything 3 storeys; (C) everything 2 storeys.
2. Default wall height at run start: (A) one storey, 5m (recommended); (B) two storeys, 10m.
3. Valley rule in the Game: (A) on (recommended); (B) off, keep settling one tier down.

## User decision (2026-11-23)

1. None of the listed options: walls (and with them bastions, stairs and the gatehouse column) up to 3 storeys (15m), towers up to 4 storeys (20m) and 2 storeys beside the default one-storey walls (one above the touching walls); the Game grid needs 4 levels, with storey 4 used only by tower tiers. Siege ladders support 5m, 10m and 15m walls. Revision trail, all on 2026-11-23: the user first chose this, then briefly switched to walls 2 / towers 3 (merged as `a00f1cd`) because 3-storey walls seemed to weaken towers, then restored this choice since a 4-storey tower still stands above a 3-storey wall.
2. Option A: one-storey (5m) default walls; the default ring uses the same kit pieces and dressing as player-built walls (no separate assets). The user first asked not to change the wall modular system, then allowed improving it for the interior stair rooms. The gatehouse stays two storeys (SIEGE-14).
3. Option A: `forbidValleys` on in the Game; a collapsed storey takes every storey above it.
- Two-storey steps: the automatic wall stairs (`CastleKitRules.AddStairs`) connect only walls one storey apart, so a one-storey wall beside a three-storey wall would be cut off. The user proposed interior stair rooms, briefly cancelled them, then restored them and answered the nine open points (below); implementation is the new task `SIEGE-27`, built in the spike before `SIEGE-18`.
- Kept as they are: no stacking on stairs, one-cell stairs (their top never above storey 3), multi-cell pieces need uniform support and are destroyed if partially unsupported, stairs behind a breach stay standing.

## Interior stair rooms (user answers, 2026-11-23)

1. Only two-storey steps use a room; one-storey steps keep the outside automatic stairs (recommended option).
2. The three-storey cell touching the lower walkway gets rooms at both the one-storey (5m) and two-storey (10m) floors.
3. Switchback stairs with a mid landing per storey (recommended; a straight 5m flight does not fit the about 4m interior).
4. A door on every face that meets a walkway at the same floor height: in a 1-3-2 row, the lower door on the one-storey side and the upper door on the two-storey side.
5. Automatic and free.
6. Recommended look (HP and outer panels kept apart from doors); improving the wall modular dressing for this is allowed. Three-storey walls later get outer decorations such as banners, after the storey work: new task `ART-08`.
7. No arrow slits.
8. Collapse follows the no-valley rule; a fallen lower neighbour leaves the door as an opening (recommended).
9. Part of the NavMesh for everyone; enemy target choice added to the open task `SIEGE-26` (not yet done) and pushed to `develop` right away at the user's request (`ab3c22e`).

## Walls taller than towers

Raised by the agent: a tower's height is set once at placement (`TowerRules.Tiers`, one storey above the tallest touching wall) and its only room is on the top storey, so raising a touching wall later could make the wall as tall as the tower. The user answered with a planned castle-wide wall tier upgrade that raises wall height and HP and unlocks structures tier by tier, growing towers automatically so walls never outgrow them. Heights are counted in wall storeys (the user dropped a separate tower "stage" unit); the cap is only a maximum and raising walls stays paid; tower height follows the tier, not the touching walls; the battlement upgrade joins the tiers, while decorations and interior stairs come from the modular dressing. Registered as `SIEGE-28` (Pending Decision, not started).
