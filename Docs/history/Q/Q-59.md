# Q-59 | 2026-11-23 | Building Tier Limits & Edge Cases

> Purpose: Decision log. | Parent: [history/README](../README.md) | Related: [Decisions-Resolved](../../plan/Decisions-Resolved.md), [Walls & Siege design](../../design/WallsAndSiege.md), [SIEGE-14](../SIEGE/SIEGE-14.md)

- Branch `feature/q-59`; youngho. Doc-only decision task; no game code, scenes or assets changed.
- Input: the [SIEGE-14](../SIEGE/SIEGE-14.md) spike already settled the valley rule, collapse of upper storeys, automatic stairs, stairs behind a breach and tower stacking for the kit. Open for the Game on 5m tiers: the maximum number of tiers, the default wall height and whether the valley rule is on.

## Options presented

1. Maximum height: (A) walls and bastions 2 storeys, towers 3 (recommended); (B) everything 3 storeys; (C) everything 2 storeys.
2. Default wall height at run start: (A) one storey, 5m (recommended); (B) two storeys, 10m.
3. Valley rule in the Game: (A) on (recommended); (B) off, keep settling one tier down.

## User decision (2026-11-23)

1. Option A: walls (and with them bastions, stairs and the gatehouse column) up to 2 storeys (10m), towers up to 3 storeys (15m); the Game grid keeps 3 levels, with storey 3 used only by tower tiers. Siege ladders support 5m and 10m walls.
2. Option A: one-storey (5m) default walls, without changing the wall modular system: the default ring uses the same kit pieces and dressing as player-built walls. The gatehouse stays two storeys (SIEGE-14).
3. Option A: `forbidValleys` on in the Game; a collapsed storey takes every storey above it.
- Kept as they are: no stacking on stairs, one-cell stairs (their top never above storey 2), multi-cell pieces need uniform support and are destroyed if partially unsupported, stairs behind a breach stay standing.

## Cancelled plans

Recorded here because the backlog has no separate list for cancelled ideas (cancelled registered tasks are closed as history files marked Superseded, like SIEGE-13 and ART-07).

- **3-storey plain walls** (first chosen by the user the same day: walls 3 storeys, towers 4, ladders 5/10/15m). Cancelled by the user before completion: 3-storey plain walls would take away the reason towers were added (their height over the walls).
- **Interior stair rooms for a two-storey height step** (raised by the user after reading that the automatic wall stairs only connect walls one storey apart, `CastleKitRules.AddStairs`): the taller wall cell would become a room per storey, with a door at the lower walkway and inner stairs. Never registered as a task; dropped with the 3-storey walls, since walls up to 2 storeys never differ by more than one storey. Open points if revived: which cell holds the room, switchback vs spiral stairs in a 4m interior, doors per matching walkway, automatic vs built, outer look and arrow slits, collapse behaviour, enemy use (`SIEGE-26`).
