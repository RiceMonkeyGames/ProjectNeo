# Q-77 | 2026-11-20 | Unstarted Build Orders at Battle Start

Last Updated: 2026-11-21 02:20:57 (KST)

> Purpose: Decision and implementation log. | Parent: [history/README](../README.md) | Related: [PrepEconomyMeta](../../design/PrepEconomyMeta.md), [Decisions-Resolved](../../plan/Decisions-Resolved.md), [WallsAndSiege codemap](../../codemap/WallsAndSiege.md)

- Raised by the user (youngho) on 2026-11-20 from a playtest: a wall or cannon order still at `0%` disappeared at battle start. This is the SIEGE-08 rule (a `0%` build order is removed and refunded in full; work only advances when preparation time is spent, e.g. by holding `T` to wait).
- Options presented: (A) a passive yellow warning line under the start-battle hint, (B) a confirmation dialog when the battle start hold completes, (C) both (dialog only when a `0%` order exists). The user chose A and kept the `0%` removal rule.
- Rule: while any work order (build or repair) is unfinished, the first-person preparation hint shows `! Unfinished work N - M not started will be removed and refunded at battle start`, or `... - enters battle at current progress` when every build order has started. Repairs at `0%` are not counted as "not started" because their target stays. No extra confirmation step.
- Code: `WorkQueue.NotStartedBuildCount` (pure), `GameConstructionWork.BattleStartWarning()`, `GameFlowHud` adds the line under the start-battle line and grows the prompt panel by one line.
- Tests: `WorkQueueTests.시작하지_않은_건설_주문만_0퍼센트로_센다` (EditMode) and warning assertions in `GameConstructionWorkPlayTests` battle-start test (PlayMode).
