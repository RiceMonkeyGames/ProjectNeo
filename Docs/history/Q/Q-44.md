# Q-44 | 2026-11-13 | Morale - Rout Wiring, Enemy Morale Removal & B-8.2 Split

Last Updated: 2026-11-13 19:28:47 (KST)

> Purpose: Decision log. | Parent: [history/README](../README.md) | Related: [MoraleAndWave](../../design/MoraleAndWave.md), [B-8.1](../B/B-8.1.md)

User decisions while preparing B-8.2 (youngho, 2026-11-13). Agent proposals were reviewed item by item; the user accepted or revised each.

1. **Scene**: Wire morale into the real `Game` scene. Morale logic lives in new components under `Morale/`; they subscribe to `GameSession.Flow.PhaseChanged` themselves, so flow code is touched only where outcome counting and results need it.
2. **Enemy morale removed**: Enemies are monsters without morale (user: like monsters without stress in Darkest Dungeon). Enemies leave only via Q-30 retreat. `Battle.asset` spawn rows are not treated as enemy squads. `MoraleSide.Enemy` stays unused for possible future human enemies.
3. **Ally retreat point**: Computed from the castle grid at the courtyard edge farthest from the enemy approach; tuned in a settings asset; no scene marker.
4. **Routing allies**: Ignore orders; exit on arrival at the retreat point; return in the next preparation phase (recorded as `Fled`).
5. **Split**: B-8.2 = morale-loss event wiring, rout movement/exit, result recording. New `COMBAT-03` = Collapse/Awaken effects in combat (attack modifiers, Fear order-ignore, Panic, Contagion) and morale HUD. (`SIEGE-03` was already used; `COMBAT-01`/`COMBAT-02` were taken on develop the same day, so the morale task became `COMBAT-03` at merge.)
6. **Member-death loss**: Proportional to the squad's member count at the start of this battle; a squad at `150` hits `0` at `90%` deaths (full-squad loss ≈ `166.7`). A squad starting at `80` therefore routs after about `48%` deaths; accepted.
7. **Storage**: Morale belongs to the run-data squad between battles; new squads (including barracks auto-created ones) start at `150`.
8. **BattleResult**: Allies record `Fled`; enemy retreats recorded per enemy type, separate from kills.
9. **Exit timing**: A routing unit counts as out of battle when it reaches the retreat point (same as Q-30).
10. **Edge cases**: Unreachable for `20s` → exits in place; battle ends while running → `Fled`; killed while running → `Dead`.
11. **Fled units next prep**: Hidden on exit; reappear at the retreat point in the next preparation phase and walk back to their squad.
12. **Defeat**: Gate intact + player alive → battle continues even if all squads routed; gate destroyed + all allies dead or exited → defeat (existing rule).

Squad merging / minimum squad size raised by the user is deferred to preparation-phase work as Q-45.

Coordination: the user shared the enemy-morale removal and the Q-45 deferral with teammate Hwang Seong-min (2026-11-13). Edits in flow/run files (`GameBattleController` alive count, `RunUnitBinding`/`GameRunLink` result fates, run squad morale storage, fled-unit restore) are part of B-8.2 and stay sequential with C-1a-confirm.

Doc-only decision record; no code or assets changed at decision time.
