# Q-13 | 2026-11-21 | Remaining Save Scope for M3

> Purpose: Decision log. | Parent: [history/README](../README.md) | Related: [FLOW-02](../FLOW/FLOW-02.md), [META-01](../META/META-01.md), [PrepEconomyMeta](../../design/PrepEconomyMeta.md), [Decisions-Resolved](../../plan/Decisions-Resolved.md)

- Background: META-01 (meta save, three slots, backups) and FLOW-02 (one run per slot, automatic saves at preparation start, battle start, reward and quit during preparation; no mid-battle save; defeat deletes the run) were built with choices delegated to the agent. Still open were saving inside a battle, manual saves, and save migration when content ids change.
- Decided by the user (SeongminHwang) on 2026-11-21:
  1. **In-battle save**: none. Quitting mid-battle keeps returning to that battle's preparation and replaying it. Options not taken: quitting counts as a defeat (blocks retrying, but punishes crashes), or a full battle snapshot (large work, many failure points).
  2. **Manual save**: no free save/load slots. Add a `Save and return to Title` action during preparation that saves at the moment quitting already saves. Options not taken: automatic only (no change), or free manual slots (save-scumming).
  3. **Content id changes**: a data rename table maps old ids to new ids; content that no longer exists is dropped from the run with a refund, so the run continues. Options not taken: drop and refund without a rename table, or keep discarding the run.
- The FLOW-02 automatic save moments are confirmed as the rule.
- Follow-up tasks registered: `FLOW-04` (Save and return to Title) and `META-10` (rename table, drop and refund). The unlock and perk UI work named in the original item was already done in META-06 and META-09.
