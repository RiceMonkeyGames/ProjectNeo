# PREP-11 | 2026-11-25 | Prep - Artisan Workforce System (Rules, Time Contention, Hiring & UI)

> Purpose: Implementation and verification log. | Parent: [history/README](../README.md) | Related: [PrepEconomyMeta](../../design/PrepEconomyMeta.md), [Decisions-Resolved](../../plan/Decisions-Resolved.md), [FlowRunEconomy](../../codemap/FlowRunEconomy.md), [WallsAndSiege](../../codemap/WallsAndSiege.md)

- Assignee: SeongminHwang. Branch `feature/prep-11` from develop `793aeea` (claim commit).
- Rule (user 2026-11-25): an explicit **Artisan** (`장인`) workforce replaces the fixed two work crews of Q-53 / SIEGE-08. Runs start with `2` artisans; construction and repair orders run on as many active slots as there are artisans, in player-set priority order. Blacksmith craft / equipment upgrade and facility upgrades (now `1` hour, data) occupy `1` artisan for their clock step, so only `N - 1` slots progress then; wait and Hero Hall promotion leave all `N` free.
- Decisions made before start (user 2026-11-25): the hire cap is gated by **Blacksmith level** (Lv1 `3`, Lv2 `4`, Lv3 `5`, data); an upgrade only opens a slot, and each hire still costs gold (`50` / `100` / `150`, data). Work queue UI is mockup **option B**: a third build bar tab `작업 N/Max` (over A, a right-docked panel, and C, an artisan chip with a pop-up list).

## Changes

- Rules: `PrepTimeSettings` gains `StartingArtisans` (renamed from `workCrews` with `FormerlySerializedAs`, so `PrepTime.asset` keeps `2`), `ArtisanCap(smithyLevel)`, `ArtisanHireGold(hired)`, `FacilityUpgradeHours` and the `WithArtisans` test factory. New `RunState` partial `RunStateArtisans.cs` (`HiredArtisans`, `ArtisanCount`, `EffectiveArtisanCount` hook for later perks / Ascension / meta, `ArtisanCap`, `NextArtisanHireGold`, `CheckHireArtisan` / `TryHireArtisan`, `CheckUpgradeFacility`), enums `ArtisanHireCheck` and `FacilityUpgradeCheck`.
- Clock contention: `PrepClock.TrySpend(hours, occupiedArtisans)` raises the new `Stepped(PrepClockStep)` before `Advanced(hours)`; `RunState.TrySpendPrepTime` passes the occupied count (`DirectActionArtisans = 1` for craft, equipment upgrade and facility upgrade). `TryUpgradeFacility` checks funds then time and spends neither when time is short (no time is charged while a battle is pending, as before).
- Work queue: `WorkQueue.Advance(hours, availableArtisans)`, `IsAssigned`, `AssignedCount`, `WaitingCount`, `MoveUp`, `MoveDown`, `MoveToFront`. `GameConstructionWork` sizes the queue from the run's artisans, listens to `Stepped`, and adds `PendingOrders`, `NameOf`, `Move`, `CancelOrder` (build = dismantle with full refund, repair = remaining-share refund) and `HireArtisan`; results show through `GameBuildEconomy.Notify`.
- Save: `RunSnapshot.hiredArtisans` (older saves read `0`, the starting artisans). Priority order is kept by the existing saved work index.
- UI: `ConstructionBarHud` work tab (`Category.Work`): cards per pending order (name, `%`, `작업 중` / `대기` tag, waiting cards dimmed, click selects with the gold frame), the tools switch to `앞으로` / `뒤로` / `작업 취소` / `장인 고용 · N골드` (`장인 가득 · 대장간 강화` or `장인 최대` at the cap), the status strip reads `작업 중 N · 대기 M` and the idle hint changes (`ConstructionHud.IdleHint`). Selecting a piece while on the work tab returns to its category. `PrepClockHud` shows `장인 N/Max` on the sidebar clock row. Facility popups: upgrade button `업그레이드 · 60골드 · 1시간 · 장인 1명`, craft / equipment upgrade details `· 준비 시간 1시간 · 장인 1명`, `시간이 부족합니다.` on a short clock. The battlements tool shows the hour and is enabled only when `CheckUpgradeFacility` passes.
- Editor: `ConstructionBarLayout` builds `Tab_Work` and `WorkTools`; `PrepHudSidebarLayout.ArtisanLabel` adds the `Artisans` label; new menu `ProjectNeo/Setup/Artisan HUD (PREP-11)` applies both to `Game.unity` (applied and saved).
