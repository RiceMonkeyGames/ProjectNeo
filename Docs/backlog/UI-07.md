## Squad organization window decisions (2026-11-23)

- Three columns: squad list | selected squad (leader + soldiers) | unassigned heroes and soldiers (shown as "stored").
- Clicking a row moves it: soldiers/heroes in column 3 join the selected squad, rows in column 2 return to storage. No move buttons, no helper captions.
- Leader slot is hero-only and may be vacant. Clicking a hero in column 3 makes them the leader and replaces the current leader (the previous leader returns to storage). Clicking the leader unassigns them like any other member.
- Full squad: soldier rows in column 3 are dimmed and not clickable. Squad count and size limits follow the existing settings; columns scroll when content overflows.
- Rows show a thumbnail slot (soldier face, hero face, larger framed leader face), left empty until portrait art exists. Squad names are plain `1부대`, `2부대`, ... No stats (attack, HP) shown.
- Unassigned units stay in storage after confirming and can be taken out later.
- Rule changes (user decision 2026-11-23, supersedes the D-8 "soldiers always belong to a squad, empty squads vanish" rule): soldiers may be unassigned ("stored", like heroes) and are hidden in the scene and excluded from battle; empty squads persist; squads are created by clicking a "new squad" row at the end of the squad list (until the squad cap) and can be deleted, which returns all members to storage as free soldiers.
- Closing (common rule for all UI-07 windows: facility, equipment `I`, squad organization `O`, perks `K`): `Esc` or the key that opened the window closes it. Verify the current close behavior of each window when implementing.
