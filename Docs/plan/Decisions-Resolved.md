## Resolved `Q-*` Table

B-7.2 scope (2026-11-18, user): B-7.2 is closed without new code. Post-battle cleanup is already in place and its no-leak check across repeated stages moves into B-9.3; enemy squad linking is dropped because enemies have no morale (Q-44); corpse explosion is dropped with no follow-up task. [Plan](M1.md).

Morale gain hooks (COMBAT-07, 2026-11-17, user): (1) a morale gain never triggers the Breaking Point Check, even across `100`; (2) a routed squad (morale `0`) receives no gain and its rout is not cancelled; (3) the sample hook is a battle-start perk effect (`PerkTrigger.BattleStart`), firing once per battle. Full skills stay in COMBAT-06, perk injection in META-02. [Rule](../design/MoraleAndWave.md).

Player HP HUD (UI-03, user decision, 2026-11-17): bottom-right health bar plus current/maximum HP numbers, visible during preparation and battle gameplay. [Rule](../design/Combat.md).

Run save and continue (FLOW-02, 2026-11-16): The user delegated the open Q-13 choices to the agent's recommendation and conventional practice, asking for a design that is easy to change. Chosen: one run per save slot; automatic saves only (preparation start, battle start, reward granted, quit during preparation), each switchable in `RunSavePolicy`; battles are never saved, so a mid-battle quit returns to that battle's preparation; quitting on the reward screen continues at the next stage and cannot repeat the reward; defeat deletes the run save; Title `Continue` only when a run save exists; `New Game` over a saved run needs a second click; an unrestorable run save is set aside and a new run starts. New UI text is English only (UI-02 decision). [Rule](../design/PrepEconomyMeta.md), [history](../history/FLOW/FLOW-02.md).

UI language (2026-11-16, user): UI text is authored in one language only; the English-then-runtime-Korean swap (`RuntimeSystemFont` captions, `korean ? … : …` branches) is to be removed and no new UI adds it. English is acceptable. Cleanup tracked as UI-02; device/language support in general stays under Q-15.

Meta save (META-01, 2026-11-16; partial Q-13): User chose (1) save right after every meta change and once more on application quit, (2) three save slots with a Title selection UI implemented now, (3) keep the previous file as a backup, read it when the main file is unreadable, and if both fail keep the damaged files and start fresh. Mid-run save and resume stay undecided under Q-13. [Rule](../design/PrepEconomyMeta.md), [history](../history/META/META-01.md).

COMBAT-04 (2026-11-16): User approved a data-driven single-hit poise vs stagger threshold system (`IsInterruptible && incomingStagger >= actionPoise`). Initial scope covers ladder pushing/raising (player, allies, enemies); ladder pushing is interruptible by both ranged and melee hits and settles back onto the wall before the balance point, whereas ladder raising is uninterruptible. Interrupted units have a `0.3s` re-interaction cooldown, and player interruptions show a temporary test HUD notice. [Rule](../design/Combat.md).

Cannon usability (SIEGE-07, 2026-11-15): The user delegated the three open choices to the agent's recommendation, to be revised after playtest if needed. Chosen: crosshair color state plus reload bar/text under the crosshair; the barrel follows the player's aim (no rotate keys); manned traverse ±90° with a cosmetic 180°/s barrel swivel; auto-fire arc ±45° and range 6–60m unchanged. [Rule](../design/WallsAndSiege.md), [history](../history/SIEGE/SIEGE-07.md).

Wall-top archers (BUG-wall-archer-los, 2026-11-15): The user delegated the three open choices to the agent's recommendation after reproduction. Chosen: (1) high-ground range bonus on, +25% from a 1.5m drop, no damage bonus; (2) no line-of-sight exception and no stepping to the wall edge (reproduction showed the footing exemption already works and the edge protects defenders); (3) `Hold` units with neither a shot nor a path stay on post. Arrow flight now covers the aimed point of an in-range target. [Rule](../design/Combat.md), [history](../history/BUG/BUG-wall-archer-los.md).

COMBAT-03 (2026-11-14): User chose Panic retreat to a point and waiting there until battle end; no automatic return or new orders during the battle. Panic stays in combat and differs from morale-0 rout/exit. Create a runtime `PanicRetreatPoint` at the existing courtyard retreat location. Shared-file edits to SquadCommander/SquadCommandCenter/GameSquadMorale/SquadCommandHud are available (user confirmed no other active editor); CharacterActor and UnitCombatAI use existing APIs. [Rule](../design/MoraleAndWave.md).

Combat consumables (PREP-04, 2026-11-15): The user delegated the open choices to the agent's recommendation. Chosen: `Q` quick-use key (data binding, revisit with Q-11), no quick-slot UI while only one consumable exists, instant heal of 35% maximum HP from item data, battle-only self-use with a shared 10s cooldown and no use at full HP. Skills stay under Q-12. [Rule](../design/PrepEconomyMeta.md), [history](../history/PREP/PREP-04.md).

Construction return-hint input (QA-build-zoom-ui-hover, 2026-11-14): User requested blocking camera wheel zoom over the bottom return-hint panel, matching the left construction UI. Apply to the Game scene and its setup generator. [Rule](../design/PrepEconomyMeta.md), [verification history](../history/QA/QA-build-zoom-ui-hover.md).
